# 08｜PC / 平板 / 移动 H5 响应式规范

## 1. 平台边界

手机浏览器和 App WebView 中的 H5 属于本项目目标；嵌入 WebView 的最终兼容性取决于实际内核、桥接与宿主设置，单独验证。React Native、Expo 原生组件、微信小程序原生组件不能直接使用 DOM 组件，另立渲染层项目。

## 2. 响应式策略

优先 CSS 解决尺寸与布局，交互能力通过 hover/pointer 媒体特性判断。不能简单用 UA 字符串决定手机，也不能把窄窗口等同触屏。键盘、鼠标和触屏可同时存在。

| 断点 | 初始取值 | 用途 |
|---|---|---|
| base | 0 | 默认手机布局 |
| sm | 480px | 大手机/小容器 |
| md | 768px | 平板/中等布局 |
| lg | 1024px | 桌面布局 |
| xl | 1280px | 宽桌面 |
| 2xl | 1536px | 大屏布局 |

断点是构建期 token。普通 CSS 变量不能直接作为通用 `@media (min-width: var(...))` 的替代实现。修改断点需要重新生成 CSS；运行时只改 JS 断点会导致样式和行为不一致，因此 v1 不支持任意运行时断点替换。

## 3. 尺寸与触控

普通布局不出现页面级横向滚动；表格、代码等确需二维空间的区域允许局部滚动并有可发现提示。手机输入框默认 16px、操作目标默认至少 44×44 CSS px，是本库的可用性设计目标；与 WCAG AA 的最低 24×24 及例外不是同一概念。

输入框可被软键盘遮挡时使用实际可视区域计算及滚动到字段，保持焦点；不要反复自动聚焦。使用 `100dvh` 时提供 `100vh` 回退；处理 `env(safe-area-inset-*)`。不要禁止用户缩放或设置 `user-scalable=no`。

## 4. 组件行为

Select/DatePicker 默认沿用相同值模型；通过显式 `presentation='auto'|'popover'|'sheet'` 改展示，auto 的阈值使用统一 md。初始 SSR 保持同一可序列化结构，挂载后再选择交互容器。

Dialog 不自动等同 BottomSheet；Drawer 支持侧边，BottomSheet 专门处理底部和拖拽。Popover 的触屏打开使用点击，Tooltip 的信息必须有可触达替代，不能把关键说明只放 hover。

Table 默认窄屏内部横向滚动。卡片模式必须显式传 `renderMobileItem` / mobile-item slot，不能随意隐藏列或猜测字段优先级。页面 TabBar 不能挡住表单底部提交。

## 5. 手势

Pointer Events 优先；处理 pointercancel、多指切换、拖出边界和纵向滚动冲突。只在确定需要阻止默认滚动的节点配置 touch-action。不要在 document 全局阻止 touchmove。所有拖动、滑动、下拉操作必须有按钮或键盘等效入口。

## 6. 测试矩阵

自动视口：320×640、390×844、768×1024、1280×800、1920×1080；额外测横屏、200% 文字、400% 页面缩放场景。浏览器模拟不代替真机：发布前至少真机 iOS Safari 与 Android Chrome 各一组关键路径，记录系统和内核版本。

设计支持目标：现代 Chromium/Firefox 当前及上一稳定版；Safari/iOS Safari 从 16.4 起为候选最低版本。M0 必须检查依赖/CSS 能力，无法实测或不满足的版本列为未验证，不对外写“完全兼容所有手机”。

真机专项：输入法、键盘遮挡、地址栏收缩、刘海与底部安全区、系统返回手势、横竖屏、下拉滚动、画中画等宿主干扰、长按选择、辅助技术。微信内置 H5 与企业 WebView 作为扩展矩阵，不与原生小程序混淆。
