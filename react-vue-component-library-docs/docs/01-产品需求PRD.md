# 01｜产品需求 PRD

## 1. 产品目标

建立一套长期维护的 Web 设计系统：同一设计语言分别服务 React 与 Vue；从 npm 安装即可运行；无需复制项目源码或安装整套业务框架；桌面和触屏场景都可操作；主题、结构扩展与业务封装有稳定接口。

主要使用者为业务前端、设计系统维护者和二次开发团队。首期不是后台管理模板、低代码平台、图表系统或后端服务。组件库不管理登录鉴权、业务权限、数据库、接口地址、支付或云存储账号。

## 2. 典型使用场景

| 场景 | 用户希望完成 | 验收证据 |
|---|---|---|
| React 后台 | 接入按钮、筛选表单、表格与弹窗 | 从打包产物安装的 React 示例 |
| Vue H5 | 接入输入、选择、底部弹层与导航 | 真机触屏、键盘弹出、横竖屏记录 |
| 多品牌应用 | 同一页面展示两个品牌主题 | 嵌套 Provider + 浮层主题隔离示例 |
| 已有设计系统 | 只复用交互，不使用默认外观 | unstyled 示例无品牌 CSS |
| SSR 应用 | 在 Next.js / Nuxt 使用组件 | 服务端导入、首屏渲染和 hydration 测试 |
| 外部开发者 | npm 安装、类型提示、按需引入、升级 | 独立 consumer fixture，无 workspace alias |

## 4. 非功能需求

组件默认不发起任何业务网络请求，不含遥测、广告或远程字体；无全局 CSS reset；模块导入不访问浏览器对象；不打包 React/Vue 运行时；不隐式全量注册。交互状态、失焦、错误、加载、禁用和空数据都必须有可验证行为。

性能指标是本项目制定的验收预算，不是已实测结果，详见 [性能预算](16-性能预算与基准测试.md)。兼容声明以实际发布矩阵为准。库级无障碍目标不代表所有业务页面自动符合 WCAG。

## 5. 范围控制

72 项拆成 P0 26 项、P1 28 项、P2 18 项，见 [组件目录](../components/README.md)。先做 10 项纵向试点，贯通主题、测试、文档与本地打包，然后扩展；不得先做 72 个空壳再补行为。

不在 v1：富文本/代码编辑器、复杂图表、地图、流程图、甘特图、音视频播放器、PDF 阅读器、Excel 引擎、原生 App 组件、微信小程序原生组件、完整低代码搭建器。这些需要独立 RFC、体积预算、依赖和许可证评估。

## 6. 成功判断

两个独立框架项目能够安装同版本 npm tarball，完成表单、弹窗和数据列表；移动与桌面交互均通过；换肤不 fork 源码；SSR 无 hydration 错误；公共 API 类型可推断；发布和回退可复现。下载量、GitHub star 和截图数量不替代这些技术验收。
