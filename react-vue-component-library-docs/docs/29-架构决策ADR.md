# 29｜已采用的架构决策摘要

状态：本需求方案的默认决定，M0 可基于证据修订。变更时记录日期、上下文、备选、结果及受影响文档，不让 AI 静默换技术栈。

## ADR-001｜双框架原生渲染

决定：共享底座、分别实现 hooks/composables 与渲染。接受两套渲染代码成本，换取框架惯用体验与可测试边界。不采用相互嵌入或代码字符串转换。

## ADR-002｜四个公共包 + 私有内联工具

决定：ui-tokens、ui-theme、ui-react、ui-vue，统一版本。内部工具不对外承诺 API、构建内联。后果：需要发布前剔除私有 runtime 依赖的检查；不建立 72 个组件独立包。

## ADR-003｜CSS 变量与共享 CSS

决定：框架外样式源、三层 token、组件部位与 unstyled。消费端无样式工具链前置要求。后果：CSS 按需依赖图和 Portal 主题桥接必须明确实现。

## ADR-004｜ESM-only 首发

决定：先保证现代 bundler / SSR 的可安装与类型一致，不输出未经验证的 CJS/UMD。后果：部分旧消费者不在首发范围，文档明示；后续双格式单独评估。

## ADR-005｜无默认业务请求

决定：Upload/搜索/分页等注入数据与 adapter，不硬绑接口库。后果：需提供完整异步状态示例和请求取消合同。

## ADR-006｜桌面与移动共用模型，展示可适配

决定：同一数据 API，布局由 CSS、复杂弹层由 presentation 调整。手势能力提供非手势替代；不为“手机版”复制另一套数据模型。

## ADR-007｜先贯通十项，再扩展

决定：M1 十项试点带测试、主题、文档、pack；P0 26，v1 54，后续 18。后果：不能一次性以文件数量当完成率，优先修底座。

## ADR-008｜人工批准后 OIDC 发布

决定：Changesets 管版本，受保护 CI 验证，npm CLI 上传审核 tarball，人工批准公开操作。初始使用显式允许的直接 npm publish；不混入尚未设计的 stage-only 流程。

## ADR-009｜日期值与时区分离

决定：DatePicker 日期字符串、TimePicker 时间字符串；绝对时间点由业务显式转换。避免用户选择一天却因隐式 Date/时区显示成前一天。

## ADR-010｜库级无障碍目标不等于应用认证

决定：默认组件有自动与人工验证；使用者改变内容/DOM/主题需重新检查。不得宣传“只要用本库就 WCAG 合规”。
