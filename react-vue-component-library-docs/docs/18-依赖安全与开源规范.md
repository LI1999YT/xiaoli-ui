# 18｜依赖、安全与开源规范

## 1. 运行时原则

组件默认不请求网络、不收集用户数据、不上传错误日志、不加载远程字体或远程脚本。使用者传入的标签默认按文本渲染；不提供无过滤的 HTML 字符串入口。需要富文本展示由业务明确选用安全渲染方案。

上传 URL、图片 URL、链接和主题导入来自外部时校验预期协议与格式；禁止把输入直接拼进 style 标签、选择器或脚本。SVG 图标默认使用受信任源码或组件；不执行外部不可信 SVG 内容。

## 2. 依赖准入

新增 dependency 记录用途、实际导入点、体积、许可证、维护状态、peer 需求、安全记录和替代方案。工具依赖放 devDependencies；可选能力不拖入所有组件入口。自动安装脚本采用允许清单并核对 pnpm 当前策略，不无差别启用所有 postinstall。

依赖升级用独立 PR，包含双框架、类型、SSR、打包和大小回归。不要用自动 `audit fix --force` 一次跨越多个 major。安全扫描结果需要可达性与影响分析，高风险确认问题阻断发布。

## 3. 内容安全策略 CSP

默认使用外部 CSS 文件，JS 不自动创建 style/script 标签。严格 CSP 项目提供预编译主题 CSS 路径，不依赖任意内联主题代码。Provider 的运行时样式变量、定位 style 与宿主 style-src-attr 策略需要在真实浏览器测试；不要声称一个 nonce 能放行所有内联 style 属性。

若业务 CSP 禁止所用动态样式机制，提供固定 CSS 主题/明确支持范围或另立定位适配设计，不能绕过策略。文档示例解释限制，而不是默认建议 unsafe-inline。

## 4. 发布安全

npm 账号启用 2FA；优先可信发布者 OIDC；发布 job 最小权限，受保护分支、标签与人工审核；第三方 GitHub Actions 固定到经核验完整 commit SHA，升级有记录。不要把 token、恢复码、私钥、公司内部 URL 放进 `.npmrc` 或示例。

构建产物、来源提交、依赖锁和发布日志关联。公开仓库公开包可按 npm 支持条件生成 provenance；它说明构建来源，不保证软件没有漏洞。

## 5. 许可证

拟采用 MIT，正式发布前确定版权持有人与年份，生成 LICENSE；第三方代码、图标、图片、字体逐项确认许可并保留要求的 notice。不能以“AI 生成”作为复制现有库代码或移除署名的理由。

本文件是工程检查清单，不代替对具体授权争议的法律判断。对不明来源素材不发布；优先使用自绘、用户授权或许可证清晰的资源。不打包容器系统字体。

## 6. SECURITY 与漏洞处理

在发布前建立 SECURITY.md，写真实安全联系渠道、支持版本与报告范围。安全缺陷通过私密渠道受理；记录复现、影响、临时缓解、修复版本与公开说明。尚无维护邮箱时不能编造，作为发布阻断信息补齐。

Watermark、disabled、隐藏按钮、前端权限配置均不提供服务端安全边界；业务授权仍由后端执行。组件库不能声称防破解或阻止用户截屏。
