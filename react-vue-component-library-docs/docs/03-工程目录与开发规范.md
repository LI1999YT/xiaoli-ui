## 2. 工具和版本

开发/发布采用 Node 24 LTS；pnpm、TypeScript、Vite、两个框架插件、vue-tsc、Vitest、Testing Library、Playwright 和 Storybook 在 M0 查询兼容组合后锁定。根 package.json 写 `packageManager` 精确版本，提交 lockfile。版本变动记录在 tracking/DECISIONS.md。

pnpm workspace 用于本地包引用；发布前必须检查其版本重写行为。[pnpm 官方说明](https://pnpm.io/workspaces)

## 3. 代码规范

TypeScript strict；禁止用 `any` 掩盖公共 API；难以推断的第三方边界使用 `unknown` 并收窄。开启 unused 检查和一致的 type-only import。泛型组件要有真实 consumer 类型测试，不能只依赖编辑器无红线。

事件监听器、定时器、ResizeObserver、IntersectionObserver、媒体查询订阅、对象 URL 和 AbortController 都必须有清理路径。初始化函数可重复调用；React Strict Mode 与 Vue 重挂载不能造成重复订阅。

纯逻辑放 internal-core；DOM 对象只在客户端 effect/mount 或显式函数调用阶段读取。所有异常必须定义“向调用方返回、组件内展示还是开发告警”，不得静默吞掉用户数据。

公共 API 变更同时更新类型、两框架规格、文档和 changeset。公共源码不包含公司业务词、真实接口、凭证、个人数据或不明来源图片。

## 4. 根 scripts 合同

M0 必须实现以下脚本；此前这些只是目标命令，不代表已经可运行。

| 命令 | 要求 |
|---|---|
| `pnpm dev:react` / `pnpm dev:vue` | 对应 playground |
| `pnpm docs:dev` | 文档门户 |
| `pnpm lint` / `pnpm typecheck` | ESLint/样式规则 + 双框架类型 |
| `pnpm test:unit` / `pnpm test:contract` | 单元与行为契约 |
| `pnpm test:e2e` / `pnpm test:a11y` | 浏览器与可访问性 |
| `pnpm build` | tokens → theme → 双框架 |
| `pnpm pack:check` | pack、解包、文件/依赖/exports 检查 |
| `pnpm test:consumers` | fixture 安装 tarball 后构建、渲染 |
| `pnpm size:check` | 指定 consumer 场景体积 |
| `pnpm release:verify` | 全部门禁，只验证、不发布 |
| `pnpm release:publish` | 显式授权后按顺序公开发布 |

Windows PowerShell 与 macOS 都应可开发。脚本用 Node 实现文件操作，避免只在 Bash 可运行的 `rm -rf`、`cp` 和内联环境变量赋值。
