# 09｜无障碍与键盘交互

## 1. 目标与责任

默认组件以 WCAG 2.2 AA 相关要求为目标，交互参考 WAI-ARIA APG；这不是第三方认证，也不能保证使用这些组件的整个网站自然合规。默认主题、组件实现与调用方内容各自承担责任。

[W3C APG 组件模式](https://www.w3.org/WAI/ARIA/apg/patterns/)；[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；[目标尺寸最低要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

普通文本默认检查 4.5:1，大号文本按条件检查 3:1；不要把所有 18px 文本都当作大号文本。非文本状态边界、图标和焦点另做检查。AA 的目标尺寸最低要求为 24×24 CSS px，并存在规定例外；本项目主要触控目标采用更大的 44×44 设计目标。

## 2. 原生语义优先

能用 button、input、select、textarea、a、table、details 等正确表达时优先使用。不要在普通数据表格上随手加 role=grid；不要把站点导航统一标成应用菜单；不要让图标按钮缺失可读名称。

字段必须有真实 label、aria-label 或 aria-labelledby。placeholder 不代替 label。帮助、错误通过 aria-describedby 关联；required、invalid、busy、expanded 等反映当前真实状态。禁止正数 tabindex 重新排序。

## 3. 键盘合同

| 模式 | 必须实现 |
|---|---|
| Button / Checkbox / Switch | 按其原生或选定模式响应 Enter/Space；不重复触发 |
| Radio | 组内方向键、合理单一 Tab 入口 |
| Tabs | 方向键、Home/End、明确自动或手动激活模式 |
| Dialog | 进入、循环焦点、Escape、关闭后恢复 |
| Select / Autocomplete | 展开、移动候选、确认、取消；保留正常文字编辑 |
| Menu / Dropdown | 按菜单模式移动与关闭；普通链接导航不冒用菜单模式 |
| Slider | 方向键、Home/End、值范围；触屏读屏另测 |
| Tree | 方向键展开/收起/移动，选择与焦点分离 |

具体按单组件规格与相应 APG 模式执行；不同模式不能拼凑互相冲突的键位。

## 4. 焦点与可见性

禁止全局移除 outline。关闭浮层后优先回到触发元素；触发元素卸载或不可用时，回到调用方指定的安全焦点目标，而不是 body 或另一个隐藏弹层。滚动、固定工具栏和弹窗不得遮挡当前焦点。

aria-hidden 区域内不能残留可聚焦节点。Modal 设置 aria-modal 前必须真实限制外部交互；不能只加属性。无动画状态下也要正确卸载和恢复焦点。

## 5. 动态信息

Toast 和普通通知使用克制的 live region，不抢输入焦点；紧急错误才考虑 assertive。loading 使用可读状态文字，Skeleton 装饰本体隐藏给读屏。进度未知时不伪造百分比。

错误不能只用红色表示；表单提交失败时聚焦错误摘要或首个错误字段，提供可导航关联。超时关闭通知要允许暂停或持久显示，关键操作反馈不能仅一闪而过。

## 6. 验收方法

自动：组件故事执行 axe 检查、键盘测试、accessible name 断言。人工：全程不用鼠标走完关键路径；VoiceOver + Safari、NVDA + 兼容浏览器；Android TalkBack 针对移动核心流程。记录实际软件版本。

自动通过不等于无障碍通过。每个发布候选记录手工结果、限制、复现步骤；P0 键盘死路、焦点逃逸、无名称输入、不可读错误为阻断项。无法完成真机/读屏验证必须标记“未测”，不得伪造通过截图。
