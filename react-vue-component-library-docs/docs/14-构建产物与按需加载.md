# 14｜构建产物、类型与按需加载

## 1. 分发合同

首期输出 ESM JavaScript、`.d.ts`、源码映射、独立 CSS、README、LICENSE。Vue SFC 预编译。JS 不自动注入 style 标签；普通 JS 根入口不自动导入 all.css。没有实现并测试的 CJS/UMD 条件不能写进 exports。

Vite library mode 负责 UI JS 构建；tokens/CSS 用独立生成流程控制每组件文件。官方默认 CSS 聚合并不自动等于按组件 CSS 拆分。构建必须显式验证组件 CSS 依赖图。[Vite 官方 library mode](https://vite.dev/guide/build.html#library-mode)

## 2. UI 包 package.json 目标示例

下面为待生成模板，`@your-scope` 和仓库地址需要替换；版本仅示例。必须由脚本从组件清单生成全部子路径，不能只发布 Button 却宣称支持目录中的所有组件。

```json
{
  "name": "@your-scope/ui-react",
  "version": "0.1.0",
  "type": "module",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "files": ["dist", "README.md", "LICENSE"],
  "sideEffects": ["**/*.css"],
  "exports": {
    ".": {"types": "./dist/index.d.ts", "import": "./dist/index.js"},
    "./button": {"types": "./dist/button/index.d.ts", "import": "./dist/button/index.js"},
    "./style.css": "./dist/style.css",
    "./base.css": "./dist/base.css",
    "./button/style.css": "./dist/button/style.css",
    "./package.json": "./package.json"
  },
  "peerDependencies": {
    "react": "^18.3.1 || ^19.0.0",
    "react-dom": "^18.3.1 || ^19.0.0"
  },
  "dependencies": {"@your-scope/ui-theme": "0.1.0"},
  "publishConfig": {"access": "public", "registry": "https://registry.npmjs.org"},
  "license": "MIT"
}
```

Vue 包更换 peer 为 `vue:^3.5.0`，不带 React 类型依赖；tokens/theme 不带两框架 peer。仓库 URL、bugs、homepage 在正式发布前填写真实地址。对需要指定构建 Node 版本的仓库设置 engines，不能把浏览器运行条件与本地构建条件混淆。

## 3. external 与私有包

将 react、react-dom、react/jsx-runtime、react/jsx-dev-runtime、vue 及它们的合法子路径设为 external。对 public dependencies 保留外部依赖并完整声明。private internal 包构建内联，不允许 dist 出现无法安装的 `@internal/...` import。

Vite 当前配置文档使用 `rolldownOptions`；实际锁定版本可能不同。M0 按该版本类型和官方说明生成，不能盲目复制旧 rollupOptions 配置或混用两种选项。

## 4. CSS 合同

**简单全量路径：**

```ts
import '@your-scope/ui-react/style.css';
import { Button } from '@your-scope/ui-react';
```

**按需路径：**

```ts
import '@your-scope/ui-react/base.css';
import '@your-scope/ui-react/button/style.css';
import { Button } from '@your-scope/ui-react/button';
```

ui-react 的 CSS 别名由构建输出，指向同版本 ui-theme 的全量/base/组件样式入口；Vue 对应别名复用同一份主题源。base 入口汇集 tokens 与基础结构，组件入口包含其必要组件 CSS 依赖但不再重复 base。复杂组件例如 Select 需要的 Popover/Spinner 样式由组件依赖清单决定，不依赖使用者猜测。

全量和按需二选一；不要在 demo 同时导入造成无法观察体积。`sideEffects:["**/*.css"]` 保留显式 CSS 导入；只设置 sideEffects=false 可能丢失样式。Tree shaking 是在 consumer production build 中检查，不是看到源码用了 export 就成立。

## 5. 类型与 ESM

React 用 tsc/经过验证的声明流程，Vue 用 vue-tsc/兼容声明流程。验证 TypeScript bundler 与 NodeNext 消费场景；发布声明中的相对路径和扩展名必须可解析。不能把 bundler 下能解析但 NodeNext 下损坏的声明直接发布。

复杂泛型 Table/Select/Form 的推断、错误 props 拒绝、ref、slots 和事件均有类型测试。没有实现 CJS 就不增加 require 字段；后续双格式需单独 ADR，包含声明格式及双模块实例风险。

资料：[TypeScript 库编译选项](https://www.typescriptlang.org/docs/handbook/modules/guides/choosing-compiler-options.html)、[npm package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/)。

## 6. pack 验收

打包后解压 tarball，检查 exports 指向的每个文件存在；不含 .env、令牌、node_modules、测试快照、公司资源；依赖无 workspace: 协议或私有包泄漏；许可证齐全；CSS 引用可解析。独立 fixtures 仅安装 tarball，不借助根 workspace alias。通过 npm 安装、pnpm 安装至少各一条消费者路径。
