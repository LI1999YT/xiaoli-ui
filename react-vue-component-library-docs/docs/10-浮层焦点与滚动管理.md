# 10｜浮层、Portal、焦点与滚动管理

## 1. 统一基础设施

Dialog、Drawer、BottomSheet、Popover、Tooltip、Select 下拉、Dropdown、DatePicker 等共用层级管理与 portal 管理；不允许每个组件自行给 body 加 overflow=hidden。

每个浮层记录 `id / parentLayerId / ownerDocument / trigger / content / modal / dismiss policy / theme owner`。DOM 服务按 ownerDocument 管理；SSR 无全局可变单例。多份库同时存在的互操作不自动保证，应通过依赖去重和显式 portal/container 集成。

## 2. 层级与关闭

后打开的同级浮层优先；子浮层必须在父层之上。Escape 仅交给最顶层允许关闭的浮层。Dialog 中打开 Select 后，第一次 Escape 关闭 Select，第二次才关闭 Dialog。外部点击根据 composedPath 与层级关系判断，不能把 portal 子内容误判为父层外部。

按下位置与抬起位置跨越内容/遮罩时不误关闭；滚动条点击、拖拽、pointercancel 和输入法组合键不应触发外部关闭。统一 `onOpenChange(false,{reason})`，受控模式仍由调用方改变 open。

## 3. 焦点策略

模态层激活后将焦点放在合适的元素；长内容可以先聚焦标题或正文起点；危险操作默认不要聚焦最危险按钮。Tab/Shift+Tab 保持在当前可操作模态层及其有效子浮层内。无可聚焦元素时给内容根节点临时焦点目标。

关闭或卸载恢复到可用 trigger；否则用 `returnFocusTo`；不能聚焦已隐藏或被 inert 的元素。非模态 Popover 默认不强制 trap，Tooltip 不接管焦点。

参考：[W3C Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

## 4. inert 与滚动锁

模态外部区域不可交互；维护原来的 inert/aria-hidden 属性，只恢复自己改过的值。不能把 portal host 的祖先一起隐藏。打开第二个模态时增加引用计数；关闭一个不解锁剩余模态。

记录原有 body 样式、滚动位置、滚动条补偿和锁定计数。桌面避免打开弹层导致布局横跳。iOS 处理 body 锁与弹层内部滚动，关闭后恢复原位置；不要盲目覆盖使用者原本的 overflow 或 padding。

## 5. 动画与生命周期

状态至少有 closed → opening → open → closing → closed。动画结束与计时兜底二者择先，保证只执行一次 afterOpen/afterClose。快速开关时取消过期关闭任务；组件在动画中卸载仍释放监听器与锁。reduced-motion / none 模式不能依赖 transitionend 才完成清理。

## 6. SSR 与容器

默认 SSR 不输出打开浮层的 portal 内容；首次 hydration 保持一致，mount 后再显示。这意味着 defaultOpen 的弹层主体不在首屏服务端 HTML 中，必须在文档明确。不用“支持 SSR”掩盖这一限制。

高级 SSR teleport/portal 注入仅在单独 fixture 验证后开放；Vue 的 Teleport 需要正确处理服务端输出与客户端定位。容器属于另一 document/iframe 时，事件、viewport、activeElement、滚动锁均使用该 document，而非写死全局 window。

主题桥接按 [主题系统](06-Design-Tokens与主题系统.md)；外部 arbitrary CSS 的作用域不会自动穿透 body portal。

## 7. 必测用例

Dialog → Select → Tooltip 三级；两个嵌套 Dialog；两个独立 Provider；自定义容器；阴影根/iframe 为扩展测试；关闭中重开；100 次挂载卸载；触发器移除；窗口缩放；软键盘；滚动容器边缘；系统减弱动画；运行中换肤。未验证 Shadow DOM 的组合不对外宣称支持。
