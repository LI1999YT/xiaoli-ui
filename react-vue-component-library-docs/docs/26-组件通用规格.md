# 26｜组件通用规格（所有单组件文档的共同基线）

## 1. 规格阅读规则

每份组件文档列出业务专属 props、状态、事件、内容扩展、部位、tokens、移动行为、异常和验收。未列出的特性不要自行添加；不存在某种状态/模型时不得为了统一强塞 value/open/disabled。

单组件文本出现 value/checked 是逻辑名称，Vue 按 [跨框架 API](04-跨框架API与类型契约.md) 映射。专属 named model 按本组件说明。`默认：—` 表示必填或由说明决定，不能自动设成空数组掩盖错误。

## 2. 适用的通用外观属性

可见根节点组件支持 React className / Vue class、style、`classNames?: Partial<Record<Part,string>>`、`styles?: Partial<Record<Part,CSSProperties>>`；需要 DOM 部位注入时支持类型收窄的 slotProps。unstyled 可由 Provider 继承/实例覆盖。ConfigProvider、Toast service 等逻辑接口按其特例处理。

size 只用于有尺寸语义的控件；density 由 Provider 继承，实例可在相关组件覆盖。无效组合开发告警；默认不抛致命错误阻断整个应用。公共 token 值只接受对应类型。

## 3. 命名部位与 CSS

根节点 `data-dui='kebab-name'`，命名部位 `data-part='partName'`，状态通过 `data-state`、`data-disabled` 等表达。`data-unstyled` 是存在性标记：仅在最终 unstyled=true 时设置，false 时删除；品牌外观选择器用 :not([data-unstyled])，必需结构规则不受该选择器限制。组件专属公共 token 形如 `--dui-button-radius`，语义 fallback 来自 theme。

单组件文档列出的部位名是公共契约。状态属性只有在真实状态存在时设置，避免 disabled='false' 的存在性选择器错误。主类名可以用于定位，但不鼓励用户依赖私有子层级。

## 4. 对外事件

模型变化最多一次；程序性 prop 更新不回发事件。用户事件回调的调用时序在单组件记录。回调抛错不导致全局资源无法清理。服务事件不能带私有框架实例；React nativeEvent / Vue 原生 Event 统一为可选 details.originalEvent。

关闭动作区分 Escape/outside/trigger/select/close-button；异步完成区分用户确认和动画完成。不要用一个 onChange 表示搜索、选择、关闭、提交四种不同事情。

## 5. 必须考虑的场景

受控/非受控（适用时）、空/零/false、长内容、文本缩放、明暗、嵌套主题、RTL、低动效、样式覆写、键盘、触屏、SSR 首次渲染、清理、无数据与失败。未支持的浏览器能力需要降级或明确限制。

## 6. 单组件最小交付

React 实现 + Vue 实现 + 共享逻辑（如有）+ 公共类型 + 共用 CSS/token + 根/子路径导出 + 独立 CSS 导出 + 双框架 stories + 用户文档 + 命名测试 + changeset。发布前有 tarball 消费验证。

## 7. 测试 ID

`Cxx-BASE-*` 为基础；`Cxx-CTRL-*` 受控；`Cxx-A11Y-*`；`Cxx-MOBILE-*`；`Cxx-THEME-*`；`Cxx-SSR-*`；`Cxx-EDGE-*`。同 ID 在两框架复用描述。组件文档的专项用例必须实现，不能只调用一个通用 snapshot。

## 8. 当前状态

本包所有组件规格均为“待实施”。P0/P1/P2 是优先级，不是已完成程度。索引里的 72 项包含 ConfigProvider、布局和反馈服务等设计系统能力，不应宣传成 72 个已经发布的可视组件。
