# 16｜性能预算与基准测试

这里全部是**拟定预算与验证方法**，未对组件实现进行基准测试，不能把这些数值当实测性能对外宣传。

## 1. 包体预算

测量固定 Vite consumer 的 production 输出，排除 React/Vue 本身的运行时体积，并分别报告 UI 增量 JS 与 CSS 的 min+gzip。不能比较不同压缩器或一个含框架、一个不含框架的结果。

| 场景 | 初始预算 | 口径 |
|---|---|---|
| 单 Button | JS ≤5KiB，所需 CSS ≤6KiB | 使用子路径；含必需共享逻辑与 base/token CSS |
| 单 Input + FormField | JS ≤10KiB，CSS ≤8KiB | 不含整套 Form 校验 |
| Dialog | JS ≤20KiB，CSS ≤10KiB | 包含必要焦点/层级工具 |
| Select | JS ≤30KiB，CSS ≤15KiB | 包含定位、集合和必要共享模块 |
| P0 全量 CSS | ≤40KiB gzip | 初始预算，实际超出走评估，不伪造结果 |
| 无关功能 | 必须无 | Button 场景不含 Table/日期/Upload 代码 |

每个主要版本可以经 ADR 调整预算，但需要提供真实 consumer diff 和原因。不能为了数字把必要依赖偷偷排除。

## 2. 渲染场景

输入 1000 字符、表单 50 字段、Select 1000 选项、Table 100×10 单元格、Toast 队列、重复打开关闭 100 次。P2 VirtualList 使用 10000 条定高数据，DOM 节点数与可见范围/overscan 相关而非与总量线性增长。

记录 CPU、内存、浏览器/系统版本、设备、throttle、数据生成种子和测试脚本。滚动目标接近显示刷新率，但不许承诺所有手机 60fps。组件库不能直接保证业务页面的 LCP/INP 总体指标。

## 3. 工程约束

避免输入导致整个 Provider 下所有组件重渲染；稳定 context 分层、memo/computed 使用以证据为依据。滚动监听避免同步布局读写交错；观察器和事件监听按作用域复用；大列表不得在每个 keydown 重新构造全部索引。

不开启所有组件默认虚拟化；虚拟化可能影响可访问性、动态高度、搜索与选区，必须 opt-in 并满足单独规格。复杂日期、上传、图标不进入基础按钮依赖链。

## 4. 内存

100 次挂载卸载/开关弹层后，不应留下持续增长的 listener、observer、timer、ObjectURL 或 detached DOM。GC 后绝对内存值会受环境影响，应报告趋势与可复现泄漏，而不是承诺一个固定 MB 上限。

## 5. 发布报告

每次候选版输出大小表、与上一版本差值、关键场景时间分布和异常说明。初版没有对比基线时写“首次基线”，不捏造“提升 50%”。
