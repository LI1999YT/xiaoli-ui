# 15｜测试策略与质量门禁

## 1. 测试分层

| 层 | 目标 | 推荐实现方向 |
|---|---|---|
| 纯逻辑单元 | 状态、集合、日期、合并、校验 | Vitest |
| 框架组件 | DOM 语义、受控、事件、清理 | Testing Library + 对应框架 |
| 行为契约 | 同一案例对 React/Vue 产生相同语义结果 | test adapter + 统一 caseId |
| 类型 | 泛型、错误 props、ref/slots、导出 | tsc、vue-tsc + consumer 断言 |
| 交互浏览器 | 焦点、键盘、真实布局、滚动 | Playwright |
| 自动无障碍 | role/name/关联等静态问题 | axe 集成 |
| 视觉回归 | 明暗、密度、部位、响应式 | 固定环境截图 diff |
| 发布产物 | tarball、依赖、CSS、SSR | consumer fixtures |
| 真机人工 | 软键盘、触屏读屏、系统行为 | 有版本与步骤的测试报告 |

Playwright 可配置浏览器/设备等 project 维度，但真实 iOS 行为不能仅靠模拟声称通过。[官方 projects](https://playwright.dev/docs/test-projects)

## 2. 行为契约

共享测试描述行为，不要求两框架的 HTML 字符串完全相等。适配器提供 mount、setProps、userClick、pressKey、readValue、getActiveElement、unmount 等能力。相同 caseId 在 React 与 Vue 均有结果，API 差异仅在适配器映射。

例 `SELECT-CTRL-001`：给定 value='a'，点击 b，收到一次下一值通知；父组件不更新时展示仍为 a；父组件更新为 b 后展示 b。不能用只测非受控场景掩盖受控 bug。

## 3. 通用矩阵

至少 default、disabled、readonly（适用时）、loading、error、empty、受控、非受控、null/false/0、长文本、RTL、明暗、嵌套主题、unstyled、卸载清理。字段增加 IME、粘贴、reset、原生 form；浮层增加嵌套、Escape、outside、焦点与滚动锁。

## 4. 覆盖率与风险

拟定门禁：internal-core statements ≥90%、branches ≥85%；P0 框架组件 statements ≥85%、branches ≥80%。覆盖率只是辅助门槛；关键行为必须有命名案例，不能通过忽略难测文件或断言空运行来达标。

纯展示组件可做比例合理的测试，不要求同一无意义断言重复 20 次。任何例外需要记录范围、理由、补齐任务和发布是否阻断。

## 5. PR 门禁

lint、typecheck、受影响单元/契约、build、关键故事 a11y、API/changeset 检查必须通过。公共 API 或底层改动增加完整双框架回归。行为变化不能只更新截图不解释原因。

## 6. 发布门禁

完整 P0+该版本承诺范围双框架测试、SSR fixtures、tarball 消费、CSS 隔离、体积预算、支持版本矩阵、关键真机与读屏记录、许可证和依赖审查、文档完整度。阻断项：无法安装、丢 CSS、重复框架运行时、hydration 错误、焦点死路、用户数据错误或明显供应链风险。

## 7. 可重复性与报告

固定时区、locale、字体回退、浏览器版本、动画设置、DPR 和视口；mock clock 用于计时测试，但真实浏览器交互保留必要时间。记录命令、提交哈希、退出码和日志路径。失败与未运行分开：`pass / fail / not-run / blocked`，不使用“预计通过”替代证据。

新增 flaky 测试必须修复或隔离并记录阻断，不无限重试到绿。截图差异由人工审查，不自动全量接受。
