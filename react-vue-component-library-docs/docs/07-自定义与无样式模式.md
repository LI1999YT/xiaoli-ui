# 07｜自定义、组合与无样式模式

## 1. 六级扩展

| 层级 | 用途 | 稳定入口 |
|---|---|---|
| L1 全局主题 | 品牌、明暗、密度、字号、圆角 | ConfigProvider / defineTheme |
| L2 单组件 token | 全局按钮高度、输入背景等 | theme.components |
| L3 实例样式 | 某一个按钮或表格 | className/class、style、局部变量 |
| L4 命名部位 | 图标、标题、列表、footer | classNames、styles、slotProps |
| L5 内容组合 | 自定义 cell、option、header、actions | React render props / Vue scoped slots |
| L6 自有外观与二开 | 复用行为或修改源码 | unstyled、有限公开 hooks、源码 fork |

每项扩展都必须展示两框架例子。不要把“支持传 style”宣传成完整高度自定义。

## 2. 稳定部位

例如 Dialog 公开 root、backdrop、positioner、content、header、title、description、body、footer、closeButton。DOM 加一层包装不应破坏基于部位的定制。使用者不要引用 `.dui-dialog > div:nth-child(2)`。

`slotProps` 为具名部位设置合法 HTML 属性；不暴露可随意覆盖的内部状态。受保护的 role、ARIA 关联、ref、禁用行为必须合并或开发告警。用户提供更有意义的 aria-label 属于允许覆盖，但不能造成两个互相矛盾的名称来源。

## 3. unstyled 合同

`unstyled=true` 可在 Provider 或单组件设置，实例设置优先。组件外观 CSS 必须以 `data-unstyled` 或等效规则隔离；即使用户已导入 all.css，unstyled 实例也不能继续获得背景、圆角和品牌边框。

无样式不等于无结构。必需的定位、隐藏、可访问焦点、碰撞位置和点击区域规则保留。v1 不承诺“完全零 CSS 的无样式体验”；对这类需求明确提供 base.css，并说明用户必须提供的结构。

## 4. 组合边界

Button 默认使用原生 button，导航使用 Typography 的 as="a"、原生 a 或业务路由链接，不把任意 div 伪装成按钮。Dialog/Popover trigger 的 render props 和 scoped slot 输出必须接收并转发事件、ARIA 和 ref。

复杂 renderCell / option slot 可改变内容，不可以随意嵌套互斥的交互元素；列表框 option 内有按钮时需重新评估交互模式，不宣称仍是普通 listbox。

## 5. 与宿主样式共存

验证宿主使用 Tailwind reset、Element/Ant 风格全局规则、CSS Modules 和自定义 reset 的场景。库自身不依赖这些技术。文档给出层叠顺序说明和最小覆盖策略。

## 6. 自定义测试

每个 P0 组件至少有默认、单 token、部位 class、替换内容、unstyled 五类示例；不适用的项目说明原因。验证样式扩展后读屏名称、键盘导航、focus-visible、禁用和表单提交不变。任意 DOM 重写不纳入库的无障碍保证。
