# 单组件开发提示词

把 `<组件ID/名称>` 替换为索引中真实项目，例如 `C14 Select`。不是让 AI 自由发挥新 API。

```text
本次任务：实现 <组件ID/名称> 的 React 与 Vue 双版本。

先读 AGENTS、tracking、对应 components 规格，以及 docs/04、06、07、08、09、26；浮层补读10，表单/异步补读11，日期/列表按专项要求补读相关组件。
检查基础依赖是否已具备；若未具备，只补本组件必需的共享原语并注明，不连带生成未规划组件。

第一步：列出公开 props、模型映射、事件顺序、ref/expose、slot/render上下文、parts、token名称、状态转换、依赖与不包含项。
特别确认 undefined/false/0/null/[]、受控父不更新、IME、disabled/readonly、程序更新不回发事件。
如发现规格冲突，在 tracking/DECISIONS 记录并统一修订后继续，不让双框架各定一套。

第二步：先实现专项 EDGE 测试及关键受控/键盘/移动/SSR失败用例，再实现纯核心、框架适配和共用CSS。
类型必须能在真正消费端推断；Vue emit 不作为可等待业务 Promise；slot透传 ref/事件/aria 有强类型和组合规则。
不把业务props泄漏到DOM，不硬编码业务接口，不为每项都强加无意义状态属性。

第三步：补双框架stories与用户文档。至少包含基础、受控、错误或空态（适用时）、自定义部位、暗色、嵌套主题、unstyled、小屏、RTL、键盘和异步边界的真实用例。
展示代码可编译；不使用截图代替交互，不使用省略号掩盖核心逻辑。

第四步：完成根/子路径/类型/CSS导出与CSS依赖图、changeset，运行组件测试、契约测试、类型、build、tarball消费及相关浏览器测试。
检查卸载后监听器/Observer/定时器/ObjectURL/滚动锁均清理。

最终按 docs/22 的DoD审查，填写真实通过/失败/未运行/阻塞，更新 TASKS 与 STATUS。没有证据不设done，不擅自发布npm。
```
