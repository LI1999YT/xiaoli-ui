# 分阶段执行提示词

使用前先让 AI 读取 AGENTS 与 tracking。一次只粘贴对应阶段，不同时要求 M0 到 M4 全部完成。

## M0 验收后：M1 十项试点

```text
读取 docs/21 的 M1 范围和退出条件。检查 M0 的实际测试与 pack/consumer 证据，不接受口头通过。
本次只开发 ConfigProvider、Button、Icon、Input、Checkbox、Form、Dialog、Toast、Flex、Card。
逐项读取 components 对应规格，以及 docs/04、06、07、08、09、10、11、26。
先建立公共类型与跨框架关键测试，再同时实现 React/Vue 与同源 CSS；loading 等必要内部原语不能冒充已完成的额外公共组件。
制作双框架同场景：字段输入/勾选、异步校验竞态、表单提交、Dialog确认、Toast反馈、局部明暗主题与已打开浮层换肤。
运行类型、契约、键盘、移动布局、资源清理、build与tarball消费检查。对未运行真机或读屏明确记 not-run。
以 docs/22 为完成定义更新 tracking，不在 M1 导出72个空壳，不公开发布。
```

## M1 通过后：M2 补齐 P0

```text
检查 tracking 中 M1 证据，核验已完成十项在当前提交仍通过。
按依赖顺序补齐组件索引剩余16项P0，总计26项。每次只取一个组件或紧密相关组件组，用单组件提示词执行。
重点检查 Select 与 Dialog/Popover 嵌套、Form 受控值、SSR/hydration、按需CSS、双框架一致性；P0 sheet 展示不依赖未完成P1公共组件。
完成 Next/Nuxt tarball fixtures、基础 i18n/RTL、完整浮层栈与文档示例。每项写真实结果，不用禁用SSR、扩大 any 或删测试通过。
所有退出条件满足后可形成预发布候选产物，但真实 npm next 发布仍需所有者明确授权。
```

## M2 通过后：M3 正式版候选

```text
按照组件索引与 docs/21 增加28项P1，使本次1.0承诺范围为P0+P1共54项。
先展示/导航，再数值和上传，再日期/表格，再移动专属组合；高风险 DatePicker/TimePicker/Table/Upload/BottomSheet 单独审查。
Table 本地处理顺序与外部分页共享状态必须完整测试；日期只用明确 date-only 值；Upload 不伪造进度和安全承诺。
同步双框架示例、文档、类型、变更记录与公共导出，不把P2实验能力默认为稳定。
执行 docs/15、16、19、20、22 的完整门禁，生成release report，列出真机/读屏/账号权限的缺项。
仅准备审核与候选包；未经批准不公开发布。没有满足承诺范围时保留beta，或提出明确缩减范围方案，不偷偷改规格。
```

## M4：后续扩展

```text
从 tracking 中选择一个有明确需求的P2组件，先提交RFC和API/无障碍/SSR/体积影响评估。
复用已完成基础，不引入全库未使用的重型依赖。新模块独立标记 experimental；不满足门禁不进入稳定根导出。
重点保证手势非唯一入口、虚拟化不伪装完整可访问列表、树形异步与勾选语义明确。
通过单组件全部验收后再决定版本与发布，不按18项文件是否存在计算完成率。
```
